# Session Handoff Standard v2.0

**Version:** 2.0
**Purpose:** Zero-drift session continuity, enforced by `scripts/session_closeout.py`
**Supersedes:** v1.0 (decision 2026-09-21-001)

---

## 1. Purpose

A session must end so that the next one starts with identical understanding of project state, and
nothing needed later may exist only in chat, scratch, a handoff, or a prompt. Under v1.0 that was a
checklist. Under v2.0 it is a gate: this standard describes what the gate enforces and the small
remainder it cannot.

`AGENTS.md` carries the baseline (constraints, conventions, cold start). A handoff never repeats it.

---

## 2. Session identity

- Sessions are numbered `S1`, `S2`, … The number is read mechanically from the newest entry in
  `sprint/sprint-status.md`, which must be headed `## S<N> — YYYY-MM-DD — <title>`.
- Session N is started by the pair `sprint/handoffs/HANDOFF_S<N>.md` + `KICKOFF_S<N>.md`, both
  written at the closeout of session N−1. The pair is named for the session that consumes it.
- A fresh project has no incoming pair; its first session is S1 and the initializer writes the S1
  sprint-status entry.

---

## 3. The one-session lifetime rule

**A handoff and a kickoff are consumed by exactly one session and then archived.** Anything that
must outlive that session is not handoff content. It goes to its durable home, and the handoff links
to it:

| Content | Home |
|---------|------|
| Work to do, its status and order | `sprint/story-tracker.md` (the kickoff cites story IDs) |
| A decision and its rationale | `sprint/decision-log.md` (the handoff cites IDs) |
| A durable learning, gotcha or rule | `docs/orchestration/knowledge/<slug>.md` + INDEX row (the handoff wikilinks it) |
| What happened this session | the `## S<N>` entry in `sprint/sprint-status.md` |
| Who the next agent should be | `.claude/agents/<slug>.md` (the kickoff names it) |

Three mechanisms hold the rule:

1. **Rotation.** `--closeout` moves every pair older than the session being closed into
   `sprint/handoffs/archive/`. The main folder holds at most two session numbers, consecutive: the
   pair this session consumed and the pair it produced.
2. **Structure.** The templates below have no section a durable rule could live in. The linter
   rejects unknown headings, unfilled tokens, unresolved wikilinks, unindexed decision IDs, and
   tasks that cite no tracker story.
3. **Reading.** Archived files are never a mandatory read. A fact left only in a handoff leaves the
   mandatory reads one session later, by design.

**Honest limit:** the gate cannot read prose. It cannot prove a sentence was not durable; the
rotation is what makes leaving it there costly rather than silent.

---

## 4. Handoff structure

Generated by `python3 scripts/session_closeout.py --scaffold --persona <slug>`. Never hand-type the
headings; the gate checks them exactly, in this order.

```markdown
# Handoff — S<N>

**For session:** S<N>
**Written by:** S<N-1>
**Written:** YYYY-MM-DD

## 1. Mandatory reads
- `AGENTS.md` cold start, then `sprint/handoffs/KICKOFF_S<N>.md`
- task-specific files, one per bullet, with why

## 2. Completed last session
- by story ID and file path

## 3. In progress
- story ID: exact state, or `- None.`

## 4. Decisions logged
- <decision ID> one-line title, or `- None.`

## 5. Blockers and open questions
- or `- None.`

## 6. Verification observed
- which gates ran and their exit codes
```

Rules the linter applies: title and `For session` match the filename; `Written by` is S<N−1>;
every section present and non-empty; section 4 is bullets whose first token is an indexed decision
ID; every `[[wikilink]]` resolves to a knowledge entry; no `{{TOKEN}}` remains.

---

## 5. Kickoff structure

The kickoff is the standalone prompt pasted into the next chat. Same scaffold command, same exact
headings.

```markdown
# Kickoff — S<N>

**For session:** S<N>
**Persona:** <slug>
**Persona version:** <the version: of .claude/agents/<slug>.md when the scaffold wrote the pair>

## 1. Persona
<one line naming .claude/agents/<slug>.md, written by the scaffold>

## 2. Cold start
Run the cold start in `AGENTS.md`. Read `sprint/handoffs/HANDOFF_S<N>.md`, then the files it lists.
Run `pre-commit run session-verify --hook-stage manual --all-files` and do no build work until it passes.

## 3. Tasks
- STORY-ID — what to do, in dependency order

## 4. Success criteria
- the executable checks that prove each task done

## 5. Closeout
<the closeout procedure of §7, naming `pre-commit run session-closeout --hook-stage manual --all-files`>
```

Rules the linter applies: the persona slug is registered, `Persona version` equals the registry's
`version:`, and section 1 is the scaffold's line (whitespace-normalized; a verbatim copy of the
agent's prompt, the rule before decision 2026-10-22-005, is accepted too); section 2 names
`AGENTS.md` and `HANDOFF_S<N>.md`; every task bullet cites a story ID present in
`sprint/story-tracker.md`; section 5 names the closeout command.

## 6. Personas

`.claude/agents/<slug>.md` holds one persona as a Claude Code agent file (decision
2026-10-22-005). Its YAML frontmatter has `name` (the slug, equal to the filename stem),
`description`, `version` (a positive integer, 1 at first release), and `expertise`, `insists_on`
and `changelog` as lists of strings; an item holding `: ` is quoted. The body is the Invocation,
the text an agent is addressed with, and nothing else, because Claude Code makes the body the
agent's prompt. `expertise` and `insists_on` are for the human choosing; `changelog` holds one item
per version, `<version> — <date> — <what changed>`.

The session holds the persona through the `SessionStart` hook, which injects the prompt unless the
session already runs as the agent. `claude --agent <slug>` is optional: it makes the prompt the
system prompt, replacing Claude Code's own whole.

**Personas are append-only** (decision 2026-09-23-002). An Invocation is never edited in place: an
enhancement bumps `version:` and appends its changelog item, and the gate refuses a body that
differs from the committed copy at the same version. The version never goes down. A bump that
changes only `expertise` or `insists_on` is allowed. A kickoff names the version the registry held
when it was written, so a reader knows which text the session was addressed with.

**Personas are shape-gated, not list-gated.** No list of future personas is predicted. When a
session's task list needs expertise no registered persona has, the agent writing the kickoff writes
the persona and registers it in the same commit. The gate proves the reference resolves and the copy
matches; it does not judge whether the persona is the right one. That judgement is the author's, and
the registry grows only from real sessions.

## 7. Closeout procedure

Run at a natural work-unit boundary, or when the user signals context is high ("Context is at
X%"), or when the user says "end session". The agent does not self-measure a percentage.

1. Finish only the current work unit. Checkpoint the tracker, decision log, and sprint-status.
2. Flush durable learnings to `docs/orchestration/knowledge/` with an INDEX row and `teaches:` /
   `verified:` frontmatter. Log every decision. Anything you would otherwise put in the handoff
   "for later" goes here instead.
3. Write or update the `## S<N> — <date> — <title>` entry at the top of `sprint/sprint-status.md`:
   Done (by story ID), Blockers. Next-session tasks do not go here; they go in the kickoff.
4. `python3 scripts/resources_sync.py --apply` refreshes the persona registry and the resource
   knowledge entries from `dev-resources` and reports what this project holds that it lacks.
   Publish that with `--publish <clone>`, commit and push there, and sync again until the stamp
   is written; step 6 refuses an unpublished persona ([[reference_resources_sync]]). The sync
   runs here, never at cold start, so the pair the next session consumes was scaffolded from the
   registry as just synced.
5. `python3 scripts/session_closeout.py --scaffold --persona <slug>` writes `HANDOFF_S<N+1>.md` and
   `KICKOFF_S<N+1>.md`. Fill every `{{FILL}}` token.
6. `pre-commit run session-closeout --hook-stage manual --all-files`. It archives older pairs and
   verifies the produced pair. Fix what it reports; never bypass it. `--all-files` matters: without
   it pre-commit stashes unstaged edits to tracked files first, and the gate judges the last
   commit's sprint-status and tracker instead of the ones you just wrote
   ([[reference_precommit_stash]]).
7. Commit `checkpoint: closeout S<N>`. The commit runs the per-commit state gate again. Push, and
   confirm the `gates` run on GitHub is green before handing over ([[reference_ci_backstop]]).
8. Give the user the kickoff file's contents as the prompt for the next session. The file is the
   source; the chat copy is a convenience.

**Emergency close** (user signals context is critical): do steps 3 and 7 with a minimal entry
headed `## S<N> — <date> — emergency checkpoint`, and say plainly that the closeout was not
completed. The next session's `session-verify` will fail, which is correct: it forces that session
to complete the closeout of S<N> before building.

## 8. Cold start

The cold start is in `AGENTS.md`, its one home; the kickoff's section 2 points there.

## 9. Story completion criteria

A story is `Done` when all of the following are true:

| Criterion | Verification |
|-----------|--------------|
| All artifacts created | Files exist in the correct locations |
| Verification run and observed | The task's executable check was run and passed, not assumed |
| Gates pass | `pre-commit run --all-files` exits 0; a commit-msg gate is tested separately |
| Standards compliance verified | The story's Required Standards checklist was applied |
| Tracker updated | Status = `Done`; Summary Statistics reconcile (gated) |
| Decision log updated | If a decision was made |
| No open questions | Or they are logged in the decision log |

---

## 10. Sprint transition

A sprint closes with the same pair. The retrospective (what worked, what drifted, what to change)
is durable, so it goes to a knowledge entry and, if it changes how sprints run, a decision. The
sprint-status entry names the sprint closed and the sprint opened; the kickoff's tasks are the new
sprint's first stories.

---

## 11. Relationship to the constitution

`AGENTS.md` points here for the closeout, and `CONSTITUTION.md` §2 points to `AGENTS.md`. Where the
constitution and this standard disagree on handoff matters, this standard governs.
